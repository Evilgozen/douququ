# 改进计划（P0-P2）

> 依据：`docs/benchmark-analysis.md` 的差距映射。优先级定义：
> **P0** = 直接提升单条视频的完播率/视觉冲击，改动小收益大，下一批视频就该有；
> **P1** = 建立差异化护城河，需要一定工程量，2-4 周内落地；
> **P2** = 长线运营能力，等账号有数据后再投入。
> 每项都给了落点文件和验收标准，实施时按验收标准跑 judge/dry 验证。

## P0（本周期，预计 3-5 个工作日）

### P0-1 ✅ 技能可视化：弹道与特效层（2026-09 已实现：fx.ts 粒子/光束/光环/碎片）
- **对标**：黑市电子斗蛐蛐（差距 A）、阿铭
- **现状**：技能只有文字弹窗 + 拳头球顶一下，"150 倍觉醒"没有任何视觉形态
- **方案**：渲染层加特效系统（`src/render/fx.ts`），由 sim 事件驱动：
  - 普通攻击：撞击点火花粒子（5-8 个，物理飞散淡出）
  - 技能：弹道拖尾（从攻击者到目标的发光线段/投射小球，100-200ms）
  - 觉醒/狂暴：球体持续冒金色粒子 + 变大 10%
  - 死亡：碎片粒子爆开（球体颜色）
  - 粒子全部走确定性 RNG（同 seed 重放一致），数量上限防爆内存
- **落点**：新增 `src/render/fx.ts`；`sim.ts` 事件流已具备（attack/crit/twist 直接消费）
- **工作量**：2 天｜**验收**：judge 抽帧确认技能/暴击/死亡有可辨识特效且无性能劣化

### P0-2 BGM 情绪层
- **对标**：所有头部内容（差距 D）
- **方案**：混音器加 BGM 层（`src/audio/mixer.ts` 已支持多 Float32 层叠加，纯实现）：
  - 素材：CC0 音乐包（Kenney 同源渠道或 pixabay music），紧张段+结算段两首
  - 剧本 `bgm: { file, vol }` 配置；结算卡淡出
  - ** ducks**：解说行播放时 BGM 自动压到 40%（按 narration 时间窗做包络）
- **落点**：`mixer.ts` 加一层；`render.ts` 传参
- **工作量**：0.5 天｜**验收**：成片有 BGM、解说清晰可闻、峰值不削波

### P0-3 ✅ 地图机关（2026-09 已实现：弹板 + 加速带，YAML arena: 字段）
- **对标**：阿铭/Algodoo（差距 B）
- **方案**：竞技场内加可配置机关（`sim.ts` physics 扩展 + YAML `arena:` 字段）：
  - **中央弹板**：场地中央一个圆形弹板，球碰到获得径向冲量（比墙反弹猛）
  - **四角加速带**：角落区域经过时获得切向加速
  - 机关触发也发 Lua 事件（`trigger: { type: 'bumper' }`），音效/演出可绑定
- **落点**：`sim.ts` 碰撞判定扩展 + `loader.ts` + `draw.ts` 画机关 + `default.lua` 音效
- **工作量**：1.5 天｜**验收**：dry 战报碰撞事件数上升；judge 帧可见机关且有球-机关交互

### P0-4 ✅ TTS 情绪化（2026-09 已实现：金色行 1.18x 速 + 0.25 音量，混音层应用）
- **对标**：Super也好君（差距 C）
- **方案**：解说词按行标注情绪档位，TTS 参数随档位变化：
  - 普通行：speed 1.1；反转行：speed 1.25 + vol 1.2（MiniMax 再叠 `emotion: excited`）
  - 结算行：speed 0.95（压低收尾）
  - 实现：caption 打 gold 标记已有 → tts.ts 按 gold/emotion 字段切参数；hash 缓存自动区分
- **落点**：`cli/tts.ts` + `loader.ts`
- **工作量**：0.5 天｜**验收**：同一集里反转行明显比普通行"亢奋"

## P1（第二周期，2-4 周）

### P1-1 ✅ 赛事化包装（2026-09 已实现 lite：npm run record + roster.json + VS卡历史交手/结算卡生涯战绩）
- **对标**：Jelle（差距 F）
- **方案**：
  - `leagues/ligue1.json`：选手注册表（角色 ID → 人设卡：名字/称号/胜场/败场/出名技）
  - 每次投稿后脚本更新战绩（复用 dry 战报输出）；结算卡加"历史交手 X:Y"一行
  - 开场 VS 卡显示双方往绩——宿命对决叙事的成本极低、效果极高
- **工作量**：2 天

### P1-2 打击感粒子包
- **对标**：Algodoo 破坏系（差距 E 的剩余部分）
- **方案**：受击形变（球体沿受击方向压扁 15% 弹回）、大伤害击飞拖尾、墙撞灰尘粒子
- **落点**：`fx.ts` + `draw.ts` drawBody 形变
- **工作量**：1.5 天

### P1-3 随机场上事件
- **对标**：阿铭的"随机生成"卖点（差距 H）
- **方案**：战斗中随机（seeded）掉落增益球（攻击+50%/护盾/回血），球碰到即拾取，配横幅播报。与剧本反转解耦的"第三种意外"
- **落点**：`sim.ts` 掉落物实体 + `draw.ts` + Lua 事件
- **工作量**：2 天

### P1-4 BO3 多回合赛制
- **对标**：黑市/电竞语法（差距 I）
- **方案**：剧本 `format: BO3`，打完一局 2 秒后重置位置再来一局（HP 重置、buff 保留与否可配），先胜 2 局者赢；结算卡报 2:1
- **落点**：`sim.ts` 外层循环包装（不动核心 step）+ 结算文案
- **工作量**：2 天

### P1-5 ✅ 镜头语言（2026-09 已实现 lite：死亡慢放+1.06 特写倒地+1.3s 后滑回全景；回放未做）
- **对标**：阿铭第一视角、Jelle 多机位（差距 G）
- **方案**：致死一击触发 0.8s 慢放 + zoom 1.3 特写 victim（复用现有 zoom 机制）；结算卡前插 2s"回放"（同 seed 重放最后 3 秒的简化渲染）
- **工作量**：2 天（回放部分可降级为慢放增强）

## 实施顺序建议

P0-2（半天见效）→ P0-1（最大视觉差距）→ P0-4 → P0-3 → 用新能力出 2-3 期看数据 → P1-1 → P1-3 → P1-2/P1-4/P1-5 按数据选 → P2 看账号体量。

**判断标准**：每批 P0 上线后，拿完播率和平均观看时长对比现有 2 集基线（B站创作中心数据）；P1 项按"哪项劣势被观众评论区主动提到"来排。
