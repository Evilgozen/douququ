# 猫 meme 技能对战制作

以现有项目的 `AGENTS.md`、代码和 YAML 为准。先确定实际工作目录；用户已切到 local 时优先使用本地项目，不默认继续改旧 worktree。通常项目在 `C:/Users/1/Desktop/My_Work/douququ`，但须先核实。

完整产出包括剧本、静态素材、透明动作帧、技能原声、演出效果、成片、质检结果；需要投稿时再准备封面、标题和投稿记录。用户只要求其中一段时完成该段，不自动投稿。

## 静态与动态技能

- 平时使用 `sprite` 静态图，按确定性物理移动；触发技能后播放透明动作帧与对应原声，技能片段结束恢复静态图。
- 当前 meme 实现在演出期间停止本体移动，技能命中由模拟中的实体碰撞决定。不要把视频回调、绘制粒子或音效随机数接入伤害判定。
- 根据用户意图选择 `timer` 或 `collision`。要求“无需碰撞”时使用定时释放，避免角色一直等接触而放不出技能。
- 让技能有可识别的机制，而不是仅闪光扣血。可先给用户少量技能候选；已选择的方案直接实现。例如伴舞分身逐个冲撞、并排双蛋共同飞行。
- 固定伤害按每个实体命中结算，单个实体只命中一次，允许落空。并排双蛋使用同一发射时刻、相同飞行进度和恒定间距，不能向同一中心收拢。
- 成长分身开启 `cloneGrowth`：首轮 1 个，第 N 轮 N 个，在发射窗口内依次冲撞，重开后归零。画面显示本轮或下轮数量；摆位须让每个分身可辨，避免中间分身被本体遮住。
- 胜负确定后停止新技能和扣血；已开始的选定音视频片段播放完再结算。等待时长纳入整期预算。

字段及当前实例见 [references/ep015.md](references/ep015.md)。优先改 YAML 和素材预处理参数；只有现有字段表达不了机制时才改引擎。

## 控制技能间隔与成片节奏

`duration` 是一次演出占用的时间，`every` 是演出结束后的冷却，`initialCooldown` 是首轮战斗开始后的等待。它们不能混为一个“技能间隔”。

对定时技能，启动间隔约为 `duration + every`，另有 1/60 秒步长误差；碰撞触发还要额外等待接触。例如 5 秒演出加 2.5 秒冷却，约每 7.5 秒启动一轮。

1. 沿用用户最近的总时长、台词长度和冷却偏好。未另设目标时，本流程可从整期 30–45 秒、单次演出约 5 秒、结束后冷却约 2–3 秒试起；这些是起点，不是所有素材的硬规则。
2. 留出开场、结尾、慢放和混音尾部的预算。当前示例开场约 4.4 秒、结尾 2.4 秒；严格要求小于 45 秒时给编码与混音留余量。
3. 跑 `--dry`，看首轮启动、后续轮数、实际命中、残血和结束时间。调整冷却会改变走位与命中，不能按旧时长简单加减后直接投稿。
4. 延长冷却时确认有可见移动和呼吸段；缩短时避免两边连续站桩播片。保持原声在单次片段内播放，不允许同角色的语音重叠。
5. 弱角色缺乏悬念时先检查技能是否能触发、命中是否过少，再调触发方式、冷却或明确的成长机制。保留用户选择的伤害和生命值；需要改数值时说明变化，不强制某一方获胜。
6. 再渲染并读取实际 MP4 时长。无慢放时 dry 是估算，有慢放时按 CLI 的模拟时间到视频时间映射检查。

## 素材与原声预处理

- 原 MP4 保留不变，放项目忽略目录 `assets/cat-meme/raw/`。从有效内容裁黑边、抠绿幕，生成透明 PNG 帧序列、静态图和 WAV；记录源文件、起点、源片段长度、输出长度、倍速、fps、帧数和裁切参数。
- 静态图选有角色的姿势，不能直接把全透明第 0 帧当静态图。
- 音画使用同一个起点和速度。视频用 `setpts=(PTS-STARTPTS)/rate`，语音提速且保留音高用 `atempo=rate`；再按最终输出时长裁切。不把音频采样率改成另一数值冒充保音高提速。
- 1.2 倍速下，源 6 秒输出 5 秒；源 7 秒需要约 5.83 秒。用户同时要求 1.2 倍和 5 秒时说明实际使用前 6 秒，不能声称完整保留 7 秒。重点检查台词结尾，不在词中硬切。
- 帧数必须覆盖输出时长，例如 15 fps × 5 秒 = 75 帧。缩短后仅清理该素材目录中超出范围的旧生成帧，保留原文件。
- WAV 时长按实际 data 帧数 / sampleRate 读取。浏览器暂停、倍速、重开、寻址与 CLI 离线混音使用同一模拟时间，避免双重播放技能原声。
- 解说与角色原声分开：当前豆包配置为 `volc-v3` / `seed-tts-2.0`；新素材原声不能误当成 TTS 重新合成。密钥只读本地配置或环境变量，不输出、不入库。

## 质检：空白帧与画面可读性

先对预处理帧做像素检查，再看成片。黑背景不等于空白帧：检查角色透明图的 alpha，而不是整屏是否发黑。

运行随技能附带的脚本，`--project` 指向项目，`--episode` 是项目相对路径：

```powershell
node <skill目录>/scripts/check-meme-frames.mjs --project C:/Users/1/Desktop/My_Work/douququ --episode public/episodes/ep015-cat-meme.yaml
```

脚本检查声明的每个动作帧是否存在、尺寸是否一致、帧数是否覆盖时长，以及是否没有或几乎没有可见像素。它不能证明角色裁切完整或音画同步，仍需视觉检查。

- **开头空帧**：如果音频已开始而画面只有绿幕，优先用首个有效姿势保持补齐空帧，保持后续动作和原声时间轴。记录补帧数。若确实要剪掉开头，则音视频统一剪，不能只跳过视频帧。
- **中间或结尾空帧**：逐段检查是源素材问题、抠像误伤还是有意演出。不能把全部空帧默默复制成第一帧；根据素材用相邻有效姿势保持、缩短片段或修抠像，并核对嘴型及台词。
- **成片抽帧**：按事件取开场滑入完成后、首次技能刚开始、发射前后、后续成长轮次、击倒与结算。技能起点附近再抽密集帧，避免只看中段漏掉瞬间消失。
- 检查标题和两侧长名字都在画面内；以滑入完成后的帧区分入场过渡与永久裁切。长名按布局可用宽度缩字号，不用屏幕边缘当截断。
- 检查 HP、技能 CD、数量、伤害、字幕和胜负卡是否可读；结算时不残留战斗字幕或未结算的瞄准线。闪白属于短暂演出，不直接当坏帧。
- 使用可用的独立 judge 做只读抽帧复核；若没有可用或获准的代理，则自己逐帧检查并报告具体证据。修正影响成片后重新渲染，旧质检只沿用未变化部分。
- 检查实际音轨：台词是否结束、是否截词、技能原声是否重复触发、解说是否与原声互相盖住。最后对 MP4 全片解码。

运行项目要求的 `check:meme-battle`、`check:audio`、`typecheck` 和 dry；动共用战斗机制时补跑 `check:rail-battle`、`check:speed-echo`、`check:assassin-speedster`。同步维护项目约束与对应检查。

## 交付与投稿

交付最新 MP4 和简短说明：总时长、演出时长、结束后冷却、启动间隔、成长/伤害机制、验证结果。文件名或发布清单应明确最终版本，避免误传旧成片。

只有用户要求发布时才上传。封面、标题、简介、分区和标签与内容一致，说明实际使用的 AI 配音或生成素材；准备工作完成后按已有授权执行，不重复询问是否投稿。

项目 `scripts/bili_login.py` 支持 `--qr-path` 保存二维码；无登录态时展示二维码让用户扫码，不代替用户确认登录。`cookies.json` 与密钥都留在忽略目录。投稿脚本使用 `scripts/publish_bili.py`，先验证登录态；封面使用完整的横向 16:10 排版，避免把竖图中间随便裁成封面。

提交前记录视频、封面、标题等清单。提交成功后保存 aid/BV 号并查询稿件状态。网络错误或返回不明确时先查询是否已有稿件，不盲目重试导致重复投稿。报告“已投稿/待审核/已发布”时以实际状态为准。
